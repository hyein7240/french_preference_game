# 데이터와 구현 구조

## 실행 구조

GitHub Pages가 HTML/CSS/JavaScript와 폰트를 제공합니다. 브라우저가 Supabase의 REST RPC와 Auth API를 HTTPS로 호출합니다. npm 런타임 의존성이나 별도 Node 서버는 필요하지 않습니다. 교사 로그인에도 별도의 외부 JS SDK를 쓰지 않습니다.

DB 자격 증명이 없는 패키지는 체험 모드로 제공됩니다. 실제 DB 연결 성공이나 사이트 배포를 가장하지 않습니다. 연결 모드의 API 오류를 체험 응답으로 대체하지 않습니다.

## 저장 데이터

| 위치 | 데이터 |
| --- | --- |
| DB `binome_private.teachers` | 교사 Auth 계정 UUID, 등록 시각 |
| DB `binome_private.rooms` | 반 UUID, 소유 교사 UUID, 반 이름, 무작위 12자리 반 코드, 제출 허용 여부, 종료/생성 시각 |
| DB `binome_private.responses` | 응답 UUID, 반 UUID, 질문에 답한 학생의 이름, 이름 중복 확인 키, 편집 토큰의 SHA-256 해시, 선택 인덱스 5개, 버전, 생성·제출·수정 시각 |
| 학생 localStorage | 이 기기에서 작성한 응답의 UUID·이름·편집 토큰·답변 임시본·버전, 마지막 반 코드와 본인 선택 |
| 교사 sessionStorage | 교사 access/refresh 토큰과 만료 시각. 비밀번호는 저장하지 않습니다. |
| 체험 localStorage | 예시와 체험 중 추가한 반·이름·답변. 실제 DB와 별도 키 사용 |

질문을 한 학생의 이름은 수집하지 않습니다. 예를 들어 A가 B의 이름으로 입력한 데이터는 **B의 선호**입니다. 실제 메시지나 검색 기록을 수집하지 않고, 해당 보기의 **선택 여부**만 저장합니다.

이름 시작 버튼을 누르면 답변 없는 초안 행을 만듭니다. 질문별 선택은 브라우저에만 임시 저장하고 최종 제출 시 5개를 함께 DB에 기록합니다. 마지막 수정 이후 다시 제출하지 않은 임시 변경은 다른 학생의 화면에 반영되지 않습니다.

## 답변 형식과 매칭

DB의 `answers`는 정수 배열입니다. A=0, B=1, C=2, D=3입니다. 다섯 문항은 `[4,4,2,2,2]`개의 보기를 가지므로 각 위치의 범위가 서버에서도 검증됩니다. 미응답이나 null 요소, 잘못된 길이/인덱스는 거부합니다.

친구 비교는 다섯 문항에 동일한 가중치를 둡니다. 자기 자신을 제외하고 같은 보기를 고른 문항 수를 계산합니다. 가장 높은 일치 개수의 친구를 모두 반환합니다. 동점은 이름 순으로 정렬하며, 4명을 먼저 표시하고 나머지는 펼칠 수 있습니다. 다섯 답이 모두 달라도 0개 일치인 친구들이 최고점 동점으로 표시됩니다.

집계와 매칭은 같은 대시보드 스냅샷에서 계산하므로 한 번 조회한 화면의 그래프와 친구 목록은 같은 데이터를 사용합니다. 미완료 응답은 어느 쪽에도 포함하지 않습니다. 자동 조회는 WebSocket 구독 대신 기본 10초 간격 폴링이며, 한 번에 하나의 조회만 실행합니다. 수동 버튼도 같은 조회 함수를 사용합니다.

## 접근 제한

| 기능 | 조건 |
| --- | --- |
| 반 확인·완료 응답 조회 | 유효하고 기간이 남은 반 코드 |
| 이름 등록 | 유효한 반 코드, 제출 허용 상태, 이름 유효성·반 내 중복 검사 |
| 답변 제출/수정 | 위 조건 + 응답 UUID + 원래 기기의 무작위 편집 토큰 |
| 반 생성/목록 | Supabase Auth 로그인 + 교사 허용 목록 |
| 반 관리·전체 작성 중 목록·삭제 | 위 조건 + 해당 반의 소유 교사 |
| 테이블 직접 읽기/쓰기 | anon/authenticated 역할에 비공개 스키마·테이블 권한을 부여하지 않음 |

테이블에 RLS를 켜고 직접 접근 권한을 제거했습니다. 공개 DB 함수는 허용 역할에만 실행 권한을 부여하고, `SECURITY DEFINER` 함수 안에서 반 코드·소유권을 검사합니다. 검색 경로는 빈 값으로 고정합니다. 공개 응답 JSON에는 원본 편집 토큰·해시·교사 정보가 들어가지 않습니다.

반 코드는 반 결과를 조회하는 공유 접근 수단입니다. 이름을 통한 강한 본인 인증은 제공하지 않습니다. 학생은 대시보드에서 자신의 이름을 스스로 선택합니다. 교실 안에서 사용할 수 있도록 반 코드 공유 범위를 관리하세요.

이름은 공백을 정리하고 대소문자를 구분하지 않는 중복 키를 사용합니다. 동명이인은 이름 뒤에 번호를 붙여 구분합니다. 한 반에 초안 포함 128개 응답, 교사당 50개 반으로 제한합니다. 사용하지 않는 반은 삭제할 수 있습니다.

DB 행 잠금과 버전을 이용해 제출/마감 요청의 경합과 같은 응답을 여러 탭에서 동시에 수정하는 경우를 처리합니다. 같은 답의 재전송은 중복 생성 없이 성공하고, 오래된 버전으로 다른 답을 덮어쓰려 하면 충돌 오류를 반환합니다. HTML 표시에는 이스케이프를 적용하며 CSV는 이름이 스프레드시트 수식으로 실행되지 않도록 처리합니다.

## 변경·운영

- 폰트는 Pretendard 1.3.9 원본 Regular/Bold WOFF2 두 파일입니다. 프랑스어 악센트와 한국어를 지원합니다. 추가 도형은 SVG/HTML/CSS로 구성했습니다.
- 새 문항/보기 개수를 추가하면 `questions.js`뿐 아니라 DB 검증·진행 단계·매칭의 문항 수를 함께 바꿔야 합니다.
- 서비스 이용량에 따른 비용이나 프로젝트 일시 중지 등은 사용 중인 Supabase 요금제와 현재 정책을 따릅니다. 수업 전 실제 프로젝트 상태를 확인하세요.
- 교사 계정 삭제는 외래 키의 cascade에 따라 해당 교사의 반과 응답을 삭제합니다.
- HTTPS GitHub Pages를 사용하면 모바일에서도 모듈·암호학적 UUID·클립보드 API를 이용할 수 있습니다. 클립보드 권한이 없을 때는 직접 코드 입력을 안내합니다.
